# 59man.shop 네이버 SEO 구조 복제 실험실 — v0.1

기준일: 2026-10-15 (KST) · 상태: **설계만 완료, 페이지 미공개**
사이트 브랜드: **59만선불폰**
개통 전환: https://preplan.site/ (59만모바일)

## 실험 질문
경쟁 사이트의 지역 URL 계층, 허브, 내부링크, 사이트맵 분할 방식 중 어떤 형태가 59man.shop의 **신규 URL 발견 → 색인 → 검색결과 등장**에 영향을 주는가?

**중요:** 경쟁사가 실제로 빠른 색인을 얻은 원인은 현재 알 수 없다. 사이트 구조를 비슷하게 구현해도 동일 순위나 속도를 보장하지 않는다. 이 실험은 경쟁사 콘텐츠/디자인/코드를 무단 복제하지 않고, 독립적인 원본 정보로 SEO 구조만 재현한다.

## 5가지 구조 모델 (+ 비교군)
1. **5분개통형: 평면 지역 허브와 지역 상세**
   - 대표 지역 허브 → 검색의도별 지역 상세 → 지역 사이트맵
   - 등록 도메인에 없는 허구의 지역/거점 정보를 넣지 않는다
2. **케어통신형: 시·구·동 계층**
   - 전국/광역 → 시군구 → 읍면동 (지리상 실제 존재하는 관계만)
   - breadcrumb와 양방향 내부 링크
3. **prepaidtelecom형: 상세 가이드 중심**
   - 준비물 → 단계 → 실패 원인 → 관련 심화 가이드
   - 실제 당사 개통 절차만 사용한다. 경쟁사 화면/설명을 복제하지 않는다
4. **테무쿠폰형: 대표 키워드 집중형**
   - 고객의 대표 검색문제에 답하는 하나의 핵심 랜딩 + 하위 의도 문서
   - 할인율/허위혜택 등 쿠폰 사이트의 주장, 스팸 백링크 방식은 재현하지 않는다
5. **테무테무형: 소규모 검색의도 클러스터**
   - 세분된 롱테일 질문 간 연결, 서로 다른 답변 범위
6. **대조군: 현재 V4.1형**
   - 동일 시기에 신규 발행하는 현행 V4.1 스타일 문서, 주제/지역/발행량 균형 유지

## 실험 설계
- **1차는 모델당 4페이지, 총 24페이지.** 지역별 수요와 난이도를 가능하면 짝지어 배분한다.
- 각 모델에서 IndexNow 알림 여부를 2:2로 나눈다 (YES/NO).
- IndexNow 미사용군에도 사이트맵 + 내부링크는 정상 제공한다. 누락/차단을 조작하는 실험을 하지 않는다.
- 동일한 도메인, 서로 다른 URL, 동일한 콘텐츠 품질 기준과 공개 시점으로 비교한다.
- 기존 19개 index 페이지, preplan.site 지역 URL과 핵심 의도가 중복되면 콘텐츠 내용을 재설계하거나 발행 보류한다.
- 24개의 원본 콘텐츠가 품질 검사를 통과하기 전에는 **일괄 생성·배포하지 않는다.**
- 최초 공개 후 1·3·7·14일간 관찰. 점수/순위 수치를 조작하지 않는다.
- IndexNow의 HTTP 200은 '요청 수신'이지 '색인 성공'이 아니다.
- 서버가 GitHub Pages로 운영되면 Yeti의 정확한 첫 방문시각을 서버 원본 로그에서 확인할 수 없다. 로그가 필요하면 별도의 프록시/수집 계층 검토가 선행되어야 한다.

## 공개 전 검증 게이트
- URL별 200, correct canonical, index,follow 확인. 404/리다이렉트 등 제외
- H1 1개, 실제 사업 정보와 망별 요금제 사실 일치, 사용자 검색의도 충족, 유용한 차별정보 제공
- 페이지별 고유 title/description/본문, 내부링크 깨짐 없음
- sitemap index/하위 sitemap에 공개 페이지만 포함, robots 허용
- 지역 계층 사실 확인, 이미지 라이선스 확인
- https://preplan.site/ 전환 링크 유지, 브랜드명을 59만선불폰으로 통일
- 실험 전/후 기존 URL·콘텐츠·검색 노출 손상 여부 점검
- 실험 기록 파일에 공개 시각/IndexNow 요청 시각·응답/색인 관측 근거를 분리 기록

## 측정값
- robots/canonical/HTTP 및 sitemap 포함 여부: 자동 검사
- IndexNow 전송시각과 응답 코드: API 요청기 기록
- 서치어드바이저 수집/색인 상태: 확인 가능한 경우만 기록
- 네이버 통합/웹사이트 검색결과의 URL 최초 관측시각, PC/모바일, 검색어, 블록/순위, 원본 결과 저장
- 실제 방문·개통 클릭: 사이트 로그/분석 도구 도입 후 측정
- 검색 결과에서 미발견은 '미노출 관측'이지 네이버 내부 DB '미색인 확정'과 다르다.

## 단계
0. 기존 19개 index URL 품질/요금제 오류(특히 396의 망 표기) 정정
1. 24개의 기획과 대조군 키워드 확정·서로 중복 제거
2. URL/허브/사이트맵/원본 HTML 템플릿 생성
3. GitHub 분기 미리보기·테스트 후 1차 공개
4. IndexNow 그룹별 요청, 노출 기록
5. 14일 경과 후 구조별 미발견·색인·검색 노출 비교, 2차 확장 판단
